# TT 网页版手机后台生成与恢复计划

## 结论

推荐做「可选的后台生成保护」，而不是承诺网页在手机后台永远不休眠。

用户开启后：普通生成由服务器继续接收并保存结果；手机切换应用、锁屏或网页被系统回收，不应仅因浏览器断连而取消已接收的任务；回到酒馆后恢复显示及保存。Agent 复用现有运行记录，在需要前端参与时明确显示等待，回来后继续，不偷偷跳过插件或提示词处理。

状态：第一阶段（普通聊天后台生成，开关「后台生成（手机）」）已实现：服务端断连不取消、内存缓冲 1 小时、页面在时自动续传。页面被回收后的恢复、Agent 恢复、屏幕常亮仍为后续阶段；尚未在真机上验收。

## 一、已核对的当前实现

以下路径均相对于仓库根目录。

1. 普通流式生成：`src-tauri/crates/tauritavern-server/src/generate.rs:163-177` 使用 `StreamDisconnectGuard`，浏览器连接关闭会取消上游。现有 SSE keep-alive 只是连接心跳，不是手机后台执行权限。
2. Agent：`src/tauri/main/api/agent-run-runtime.js` 已有 `listRuns`、`readEvents`、`afterSeq` 和轮询订阅；应复用，不另建 Agent 运行系统。
3. Agent 并非完全脱离网页：
   - `src/tauri/main/api/agent-chat-commit-bridge.js` 接收 `chat_commit_requested`，调用现有 `saveReply`、清理流程和聊天保存，再确认提交。
   - `src/tauri/main/api/agent-prompt-assembly-bridge.js` 在网页执行提示词组装并回传。
   - `tt-application/src/services/agent_runtime_service/commit.rs` 会进入 `AwaitingHostCommit`，等待前端确认或取消。
   - 同目录 `prompt_assembly.rs` 也等待前端回复。因此「Agent 在服务端跑」不等于「网页消失后所有步骤都能完成」。
4. 原版 TT Android 原生路径：仓库 `docs/AndroidDevelopment.md:218-239` 描述原生前台服务保活和完成通知。这依赖 Android 原生能力，普通网页/PWA 无法直接调用或照搬。
5. 未验证酒馆助手有能覆盖本部署的后台保活功能；不可在交付中把某插件写成已证明有效的解决方案。

## 二、选型

| 方案 | 能解决什么 | 本计划决定 |
| --- | --- | --- |
| Screen Wake Lock | 页面可见时防止自动熄屏 | 独立可选功能，不冒充切应用保活 |
| 静音音频、视频、NoSleep 类脚本 | 某些浏览器可能延缓休眠 | 不作为默认方案；没有真机证据不承诺有效，也不抢占 TTS/音乐 |
| 心跳、WebSocket、Worker、Service Worker | 连接维护、事件处理等 | 不用作永久后台运行保证 |
| Android 原生前台服务 | 原生应用后台执行 | 仅供参考，不要求网页版用户安装 APK |
| 服务端继续生成 + 返回恢复 | 手机网页停止执行时仍能保留生成任务和结果 | 主方案，适配 TT 现有调用及保存流程 |
| 酒馆助手等插件 | 提供设置入口或调用宿主已有能力 | 可以复用已验证接口；不为此强制安装大型依赖 |

浏览器可以冻结、回收页面。目标是「网页睡了，任务和结果不丢」，不是与手机操作系统争抢后台优先级。

## 三、用户设置及明确边界

在 TT 现有设置 UI 中加入「手机后台与恢复」，只在 server/web host 显示后台生成选项；不改原生 TT 的保活路径。

### 主开关：后台生成保护（默认关闭）

说明文案：

> 开启后，已被服务器接收的生成会在切换应用或断网后继续，仍会产生 API 费用。返回后恢复结果；Agent 遇到需要网页处理的步骤会等待。点击“停止”才会主动取消。

- 选择保存在当前浏览器的现有设置机制中，按登录身份命名空间隔离；共享同一 TT 账户的设备不要因全局设置互相强制开启。
- 每次发起任务时把选项固化在任务上。生成中修改开关只影响下一次任务，当前任务可单独停止。
- 关闭：不新增后台保护，保留现有调用、取消与插件语义；尤其不能把当前 Agent 的既有行为改成隐藏页面就取消。
- 开启：普通生成使用可恢复任务；Agent 接入可恢复订阅与待处理回调。
- 只有服务器已确认接收，UI 才显示「已交给服务器，可切换应用」。发送前或提示词仍在本地组装时，不显示这一保证。
- 状态区分：生成中、已生成待同步、等待网页处理、正在恢复、已完成、已停止、失败/已中断。

### 辅助开关：生成时保持屏幕常亮（默认关闭）

- 仅使用支持浏览器中的 `navigator.wakeLock`，只在可见页面且有活动生成时申请。
- 结束、停止、关闭开关时释放；回到前台按需重申请。
- 权限拒绝或不支持时明确提示，不转用隐藏音频补救。
- 不影响主开关，不承诺切换应用后继续持有唤醒锁。

完成推送不是此次功能的前提；不强制请求通知权限。

## 四、实施步骤

### A. 先确定真实接入点与兼容契约

沿网页实际请求追踪普通流式、非流式、Agent 三条路径。不要只改桌面端 Tauri 拦截路由。

重点文件：
- `src-tauri/crates/tauritavern-server/src/generate.rs` 及现有路由注册、共享状态。
- `src/script.js` 的生成、停止、`saveReply`、保存及插件事件处理。
- `src/tauri/main/api/agent.js`、`agent-run-runtime.js`、`agent-run-event-subscription.js`。
- `agent-chat-commit-bridge.js`、`agent-prompt-assembly-bridge.js`。
- 现有设置、生命周期 flush、聊天身份与持久化接口。

只读检查实际安装的酒馆助手/其他插件版本和公开 API。如果插件已提供功能，先验证其断连后的行为：仅播放音频或保持亮屏，不等于完成主需求。选定一个宿主实现所有者，不让插件与核心同时接管生成。

### B. 普通生成：连接订阅与任务执行分离

1. 关闭开关时走原路径；开启时在发送前完成现有提示词、世界书、宏、插件处理，并等待用户输入及必要聊天状态保存成功。
2. 为一次生成创建稳定的请求 ID。服务器确认接收后执行模型请求，浏览器只是读取进度的订阅者。
3. 复用已有 `ChatCompletionService`、取消机制及磁盘存储模式，增加最小的任务记录与结果读取能力；不要引入 Redis、独立队列服务或第二套模型客户端。
4. 任务记录至少包含归属、聊天稳定身份、生成类型和目标消息/分支、基础聊天版本、状态、结果位置及有序进度。不得把密钥、认证头或完整请求凭据写入恢复记录和日志。
5. 后台模式的上游取消只来自显式停止、执行时限或真实失败；浏览器 SSE/HTTP 连接断开只解除订阅。不能简单删除旧 `StreamDisconnectGuard` 而不补结果保存与回收。
6. 流式与非流式都覆盖。流式可继续显示实时输出，但最终结果必须在服务端落盘，并能重新获取。限制输出大小、缓冲区及任务并发，不因无人读取无限攒 token。
7. 发起请求 ACK 丢失时按同一 ID 查询或幂等确认，不另发一次模型请求。恢复也只读取同一任务，不自动重新生成收费。
8. 保留合理的执行时限与终态保留期，向用户说明；运行中或尚未确认领取的结果不可被当作普通临时缓存立即删除。服务器重启后把未完成记录标为中断，保留已落盘内容，不伪装自动续跑。

### C. 返回前台：恢复到原聊天，而不是覆盖当前页面

1. 在页面初始化、`pageshow`、变为 visible 及网络恢复时查询未完成/未领取任务；合并并发恢复触发，避免多个轮询器和重复处理。
2. 用稳定聊天身份、消息/分支标识、基础版本确认目标，不使用当前选中的角色作为默认目标。
3. 正常返回当前聊天时，复用现有清理、正则、`saveReply`、持久化与插件事件流程。不能直接把原始模型文本塞进 JSONL，绕过 TT 语义。
4. 用户切到了另一个聊天：显示「原聊天有待恢复结果」，待打开目标聊天后应用。不得写入新聊天。
5. 原聊天已编辑、删除、回滚或消息分支改变：保留结果并提示冲突，提供查看/手动采用，不自动覆盖。
6. 用任务 ID 加目标提交标记实现服务端可验证的幂等保存和领取确认。先保存成功再确认；在“保存成功但 ACK 丢失”后重试也不能追加第二条回复或重复副作用。
7. 多标签页同时恢复时只能有一个提交者；后端检查必须兜底，不能仅依赖浏览器内存锁。
8. 保留现有插件事件顺序和正常生成次数。不重播全部历史 token/event 来模拟新生成。第三方插件自身的任意外部副作用不能承诺 exactly-once，需实测并列出限制。

### D. Agent：复用日志，补重挂载，不假装全后台自治

1. 复用 `listRuns`、`readEvents`、`afterSeq` 和现有工作区，不把 Agent 再包进普通生成任务。
2. 返回或重新加载时，为原 run 重新挂载进度、提交、提示词组装、持久化元数据回调。只恢复时间线 UI 不算恢复 Agent。
3. 分别管理“事件已显示”和“回调已成功处理”的进度。请求失败或处理未完成时，不能因为轮询游标前移就永远跳过它。
4. 通过后端待处理状态恢复请求；对提交、提示词组装、元数据更新分别确认是否已完成。现有内存 Set 不能作为刷新后或跨标签页防重的唯一依据。
5. 网页被挂起时，能在服务器完成的模型/工具步骤继续；需要网页处理时进入真实的等待状态，保留运行与待处理数据。恢复后按同一请求 ID 继续处理，不从头启动 Agent。
6. 显式停止仍能解除等待并取消后续模型调用。待处理请求要有可见状态、有限资源占用和可清理策略，不能永久无限堆积。
7. 不把浏览器插件、世界书或正则仓促重写到 Rust，也不静默跳过。提示词组装、`saveReply` 等仍需网页时，明确显示「等待返回酒馆继续」。

边界：本方案保证可恢复，不保证复杂 Agent 在网页完全不运行的情况下走完所有步骤。若要求这一点，需要另行设计前端语义的服务器执行宿主，不应作为保活小功能暗中引入。

### E. 补 UI 与常亮辅助

使用 TT 现有设置组件、翻译机制、host 能力检测和生命周期安装方式。默认关闭，升级不替用户开启。常亮只负责屏幕，不修改全局 fetch、不拦截其他插件音频、不注册第二套 Service Worker。

停止按钮与后台设置分开；不要把关闭开关解释成丢弃正在生成的结果。

## 五、必须执行的验收

先使用可控、低成本的生成输入证明断连恢复，再用实际配置进行一次短输出端到端验证。只隐藏桌面标签页不能替代手机验收。

| 场景 | 通过标准 |
| --- | --- |
| 开关关闭 | 原生成、停止、插件行为不变 |
| 开关开启，普通流式/非流式 | 收到服务器接收确认后切应用，后台结果可恢复，不多发模型请求 |
| 切应用 30 秒、2 分钟、5 分钟；锁屏 | 返回后普通结果完整；Agent 继续或明确处于等待网页状态，不假报完成 |
| 页面被回收、刷新或重新打开 | 根据服务端记录恢复同一任务；不重复回复或计费 |
| Wi-Fi/移动网络切换、短时断网 | 重连读取同一任务，不启动第二次生成 |
| Agent 在 commit / prompt assembly 等待时挂起 | 返回后恢复原请求；提交和元数据不重复 |
| 切聊天、编辑消息、swipe、重新生成、群聊 | 不串聊天、不覆盖新内容；冲突有结果可取 |
| 两个标签页同时恢复 | 只提交一次；其他页面重新同步已保存聊天 |
| 用户显式停止 | 服务器停止后续执行；不得因重连自动继续；停止无法撤销已产生的上游费用 |
| TTS、音乐、酒馆助手、已装提示词/正则插件 | 不抢音频、不重复触发生成、不跳过保存清理链路 |
| 服务器重启、任务过期、认证过期 | 显示准确状态，保护已有结果；不无限转圈或自动重发 |
| 常亮拒绝/系统释放 | 主功能不受影响，不虚报常亮生效 |

真机至少：Android Chrome、iPhone Safari；有 PWA 使用需求时加主屏幕安装模式。记录 OS、浏览器版本、省电模式、切后台时长及结果。不支持的组合明确列出。

最低回归覆盖应守住四个真实风险：断连不取消已托管任务、Stop 确实取消、ACK 丢失恢复不重复提交、聊天版本冲突不覆盖。按仓库现有测试约定执行，完成后运行要求的检查。没有手机真机时标注未验收，不能写成“已全面适配手机”。

## 六、不做的内容

- 不用“心跳/屏幕常亮/安装 PWA”替代后台恢复。
- 不强制安装酒馆助手，不自动安装未知保活脚本。
- 不使用静音循环音频作为可靠性基础；不默认占用媒体会话。
- 不添加 Web Push、后台定时生成、自动重试收费任务、原生 APK 或独立任务服务。
- 不承诺服务器故障时无损续接未完成的上游请求。
- 不扩大已有登录账户的数据访问权限；恢复、停止、结果读取必须沿用认证与任务归属校验。
